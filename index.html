    Public recordings open without signing in. Private repositories use your existing GitHub access.

    GitHub access Optional

    A token can raise API limits and read private repositories. It is sent only to api.github.com, held in memory, and never saved or included in shared links.

    Fine-grained tokens need read access to Issues and Pull requests for the selected repository. Private media may still require a local copy. Tokens do not bypass video-host download limits.

      Add context to a recording

      Upload a video to a GitHub issue, pull request, or comment. Put a video-navigator HTML comment below its URL.

      The JSON inside the comment names the same video and supplies timestamps in seconds. GitHub hides the comment; Video navigator reads it from the raw Markdown.

      Example Markdown

      Link directly to a recording

      Use ?url=ENCODED_GITHUB_LINK. Add &t=12.5 for a timestamp or &video=2 for the second video in the same body. The Share button builds these links for you.

      A few useful rules

      • Each video has one metadata block. Its video URL must match a visible video in the same body.
      • Chapter timestamps increase strictly. Notes are ordered by time; notes at the same time appear together.
      • Notes stay current until the next timestamp, including when you seek backward.
      • Titles, descriptions, and notes are plain text, not executable HTML or Markdown.
      • With a body link, the first video-containing body or comment is opened. Use a comment permalink to choose another.
      • Private access uses an optional in-memory token. Media playback depends on the browser's GitHub access, not the API token.
